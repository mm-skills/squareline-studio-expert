# Font Documentation

This document covers font handling in SquareLine Studio — built-in fonts, custom font
conversion using `lv_font_conv`, the `.fcfg` metadata format, and glyph subsetting strategies.

---

> [!WARNING]
> - **No odd sizes**: Do not use odd sizes for built-in Montserrat (e.g., `montserrat_15`).
> - **Max size**: Nothing above 48 without creating a custom font.
> - **No Montserrat prefix for custom fonts**: Don't name custom fonts starting with
>   `montserrat` to avoid collisions with built-in names.

## Custom Fonts with `lv_font_conv`

For any font beyond the built-in Montserrat set — different typefaces, non-standard sizes,
icon fonts, or glyph-subset optimised fonts — use the `lv_font_conv` converter that ships
with SquareLine Studio.

### The Converter Binary

SLS bundles a standalone `lv_font_conv` binary (v1.5.3). The binary name is
platform-specific:

| Platform | Binary Name | Default Location |
|----------|-------------|------------------|
| macOS | `lv_font_conv-osx` | `/Applications/SquareLine_Studio.app/Contents/MacOS/lvgl/` |
| Linux | `lv_font_conv-linux` | `<SLS install dir>/lvgl/` |
| Windows | `lv_font_conv.exe` | `<SLS install dir>\lvgl\` |

> [!TIP]
> The converter is a self-contained binary — no Node.js or npm required. It's the same
> tool available via `npx lv_font_conv`, but pre-packaged.

### The 3-File Requirement

For each custom font, SLS requires **three files** in the project's `assets/fonts/` directory:

| File | Generated By | Purpose |
|------|-------------|---------|
| `ui_font_<Name>.c` | `lv_font_conv --format lvgl` | LVGL C source with glyph bitmaps (used at firmware build time) |
| `ui_font_<Name>.bin` | `lv_font_conv --format bin` | Binary font for SLS preview rendering |
| `ui_font_<Name>.fcfg` | Created manually (JSON) | SLS metadata: source TTF, size, ranges, conversion params |

> [!CAUTION]
> All three files must exist. Missing the `.bin` causes SLS to show placeholder squares
> in the preview. Missing the `.fcfg` causes SLS to not recognise the font at all.
> Missing the `.c` means the firmware won't compile.

### Step-by-Step: Adding a Custom Font

#### 1. Place the TTF source font

Copy the `.ttf` file into the project's `assets/fonts/` directory:
```
my_project/
  assets/
    fonts/
      DMSans-Regular.ttf    ← source font
```

#### 2. Generate the `.c` file (LVGL source)

```bash
/Applications/SquareLine_Studio.app/Contents/MacOS/lvgl/lv_font_conv-osx \
  --font assets/fonts/DMSans-Regular.ttf \
  --size 14 \
  --bpp 4 \
  --format lvgl \
  --range 0x20-0x7f \
  --no-compress --no-prefilter \
  --lv-font-name ui_font_dm_sans_text_14 \
  -o assets/fonts/ui_font_dm_sans_text_14.c
```

#### 3. Generate the `.bin` file (SLS preview)

Same command but with `--format bin` and no `--lv-font-name`:
```bash
/Applications/SquareLine_Studio.app/Contents/MacOS/lvgl/lv_font_conv-osx \
  --font assets/fonts/DMSans-Regular.ttf \
  --size 14 \
  --bpp 4 \
  --format bin \
  --range 0x20-0x7f \
  --no-compress --no-prefilter \
  -o assets/fonts/ui_font_dm_sans_text_14.bin
```

#### 4. Create the `.fcfg` metadata file

Write the JSON config so SLS knows the font's parameters:
```json
{
  "codename": "dm_sans_text_14",
  "ttf_path": "/assets/fonts/DMSans-Regular.ttf",
  "bin_path": "/assets/fonts/ui_font_dm_sans_text_14.bin",
  "c_path": "/assets/fonts/ui_font_dm_sans_text_14.c",
  "cfg_path": "/assets/fonts/ui_font_dm_sans_text_14.fcfg",
  "size": 14,
  "bpp": 4,
  "letters": 0,
  "ranges": ["0x20-0x7f"],
  "symbols": "",
  "customparams": "--no-compress --no-prefilter",
  "uploaded": false
}
```

#### 5. Use the helper script (recommended)

The `scripts/convert_font.py` helper generates all 3 files in one command:
```bash
python3 scripts/convert_font.py \
  --font assets/fonts/DMSans-Regular.ttf \
  --name dm_sans_text_14 \
  --size 14 \
  --range 0x20-0x7f \
  --output assets/fonts/
```

### Key `lv_font_conv` Arguments

| Argument | Required | Description |
|----------|----------|-------------|
| `--font <path>` | Yes | Source TTF file path. Can be used multiple times to merge fonts. |
| `--size <px>` | Yes | Output font size in pixels |
| `--bpp {1,2,3,4,8}` | Yes | Bits per pixel for antialiasing. Use **4** for smooth text. |
| `--format {lvgl,bin,dump}` | Yes | Output format. Run twice: `lvgl` for `.c`, `bin` for `.bin`. |
| `-o <path>` | Yes | Output file path |
| `--range <range>` | No* | Unicode range(s). Can be repeated. E.g., `0x20-0x7f` |
| `--symbols <chars>` | No* | Individual characters to include. E.g., `0123456789.°` |
| `--no-compress` | **Always** | Disable RLE compression (required for SLS compatibility) |
| `--no-prefilter` | **Always** | Disable bitmap line filter (required for SLS compatibility) |
| `--lv-font-name <name>` | For `lvgl` | Sets the C variable name. Use `ui_font_<codename>`. |

\* At least one of `--range` or `--symbols` must be specified.

> [!WARNING]
> **Always pass `--no-compress --no-prefilter`**. Without these flags, the generated
> binary format is incompatible with SLS's preview renderer.

## The `.fcfg` Schema

The `.fcfg` file is a JSON metadata file that SLS reads to understand a custom font's
configuration. It does NOT contain font data — it describes how the font was generated.

```json
{
  "codename": "dm_sans_text_14",
  "ttf_path": "/assets/fonts/DMSans-Regular.ttf",
  "bin_path": "/assets/fonts/ui_font_dm_sans_text_14.bin",
  "c_path": "/assets/fonts/ui_font_dm_sans_text_14.c",
  "cfg_path": "/assets/fonts/ui_font_dm_sans_text_14.fcfg",
  "size": 14,
  "bpp": 4,
  "letters": 0,
  "ranges": ["0x20-0x7f"],
  "symbols": "°·×✕…—–€£",
  "customparams": "--no-compress --no-prefilter",
  "uploaded": false
}
```

### Field Reference

| Field | Type | Description |
|-------|------|-------------|
| `codename` | string | Font name used in `.spj` widget references (no `ui_font_` prefix) |
| `ttf_path` | string | Project-relative path to source TTF file (use forward slashes) |
| `bin_path` | string | Project-relative path to generated `.bin` file |
| `c_path` | string | Project-relative path to generated `.c` file |
| `cfg_path` | string | Project-relative path to this `.fcfg` file |
| `size` | integer | Font size in pixels |
| `bpp` | integer | Bits per pixel (1, 2, 3, 4, or 8) |
| `letters` | integer | Legacy field. Use `0`. (SLS sets this to `3` for some range-based fonts, but `0` works universally.) |
| `ranges` | string[] | Unicode ranges included (e.g., `["0x20-0x7f"]`, `["0xE056"]`). Empty array `[]` if using `symbols` only. |
| `symbols` | string | Individual characters included beyond ranges. Empty string `""` if using ranges only. |
| `customparams` | string | Extra `lv_font_conv` flags. Always `"--no-compress --no-prefilter"`. |
| `uploaded` | boolean | Whether the TTF was uploaded via SLS Font Manager GUI. Set to `false` for programmatically created fonts. |

### Path Conventions

- All paths in `.fcfg` are **project-relative** (start with `/assets/...`)
- Use **forward slashes** on all platforms. SLS accepts both, but forward slashes are cleaner.
  (SLS's own examples use backslashes due to Windows origin — ignore that.)

## Glyph Range Strategies

Choosing the right glyph set is critical on embedded targets where flash space is limited.
Larger fonts at high bpp consume significantly more space.

### Common Range Presets

| Strategy | Ranges | Symbols | Use Case |
|----------|--------|---------|----------|
| **ASCII text** | `["0x20-0x7f"]` | `""` | English text, basic punctuation (96 glyphs) |
| **ASCII + extras** | `["0x20-0x7f"]` | `"°·×✕…—–€£"` | English text with common UI symbols and currency |
| **Latin Extended** | `["0x20-0xff"]` | `""` | Western European text with accented characters (224 glyphs) |
| **Numbers only** | `[]` | `"0123456789.°-:+%"` | Temperature displays, numeric readouts |
| **Numbers + units** | `[]` | `"°CF0123456789+-.%"` | Thermostat/unit displays |
| **Icon font** | `["0xE056", "0xE087", ...]` | `""` | Individual icon code points from icon fonts |

### Size Impact

Approximate `.bin` sizes for a typical font at 4 bpp:

| Glyph Set | Size 14px | Size 24px | Size 80px |
|-----------|-----------|-----------|-----------|
| Numbers only (~15 glyphs) | ~1 KB | ~3 KB | ~48 KB |
| ASCII (96 glyphs) | ~7 KB | ~22 KB | ~250 KB |
| Latin Extended (224 glyphs) | ~15 KB | ~48 KB | ~500 KB |

> [!TIP]
> For large display fonts (40px+), always use symbol subsets. A full ASCII range at 80px
> costs ~250 KB — but if the font only shows temperatures, you only need 15 glyphs (~48 KB).

### Icon Fonts

Icon fonts (Lucide, Material Symbols, FontAwesome) use Unicode code points in the
Private Use Area (PUA). Each icon is a single code point.

To use an icon font in SLS:
1. Find the code points for the icons you need (check the font's documentation)
2. Specify each code point as a separate range entry:
   ```json
   "ranges": ["0xE056", "0xE087", "0xE0B4", "0xE0D2"]
   ```
3. Or use a range for a contiguous block: `"0xE050-0xE060"`

Example from a working project using Lucide icons:
```bash
python3 scripts/convert_font.py \
  --font assets/fonts/lucide.ttf \
  --name lucide_24 \
  --size 24 \
  --range 0xE056 --range 0xE087 --range 0xE0B4 \
  --range 0xE0D2 --range 0xE0F5 --range 0xE140 \
  --output assets/fonts/
```

### Combining Ranges and Symbols

You can use both `ranges` and `symbols` together. The converter merges them:
```bash
python3 scripts/convert_font.py \
  --font DMSans-Regular.ttf \
  --name dm_sans_text_16 \
  --size 16 \
  --range 0x20-0x7f \
  --symbols '°·×✕…—–€£' \
  --output assets/fonts/
```
This includes all 96 ASCII characters PLUS the individual extra symbols.

## Referencing Custom Fonts in `.spj`

Custom fonts are referenced by their **codename** (the value from `.fcfg` `codename`),
NOT the filename or `ui_font_` prefixed name.

In widget style properties:
```json
{
  "strtype": "_style/Text_Font",
  "strval": "dm_sans_text_14",
  "InheritedType": 3
}
```

For built-in fonts, the strval is the standard name (e.g., `"montserrat_14"`).

Custom and built-in fonts can be freely mixed within the same project. For example,
a project might use `dm_sans_text_14` for body text and `montserrat_12` for small labels.

Custom fonts must be declared using `LV_FONT_DECLARE(ui_font_<codename>)` in firmware
code. SLS's code export handles this automatically.

## TTF Font Sources

### Fonts Bundled with SLS Examples

SLS example projects include TTF source files that can be reused:

| Font | Weights Available | Found In |
|------|-------------------|----------|
| **Montserrat** | All 22 weights (Thin → Black, regular + italic) | `SmartWatch_392x392/assets/fonts/` |
| **Lato** | Regular, Medium, Bold, Black | `Caffee_Machnine_800x480/assets/` |

To use these, copy the TTF from the example project into your project's `assets/fonts/`.

The full Montserrat family path:
```
/Applications/SquareLine_Studio.app/Contents/examples/SmartWatch_392x392/assets/fonts/
```

### External Font Sources

- **Google Fonts** (https://fonts.google.com) — large library of open-source TTF fonts
- **Lucide** (https://lucide.dev) — clean icon font with individual Unicode code points
- **Material Symbols** — Google's icon font
- **FontAwesome** — popular icon font (check license for embedded use)

> [!NOTE]
> Always verify the font license permits embedding in firmware binaries. Most Google Fonts
> use SIL Open Font License (OFL) which permits this.

## Font Properties in Widgets

In widget styles, fonts are represented by InheritedType 17 (`fontval`).
They are referenced via `_style/Text_Font` (InheritedType 3) in the styles structure.
